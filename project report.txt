Build a complete, production-ready **React + TypeScript web application** called:

# MEESHO PROFIT CALCULATOR

This is a tool for a Meesho seller to upload their actual Meesho payment Excel report, enter their **SKU purchase cost including GST**, and accurately calculate their profit/loss.

The application must be functional, not just a UI mockup.

---

# 1. MAIN PURPOSE

The workflow should be:

1. User uploads a Meesho Excel payment report.
2. Application reads the workbook in the browser.
3. Application identifies and processes the Meesho sheets.
4. Application extracts orders and Supplier SKUs.
5. User enters the **actual purchase price per unit INCLUDING GST** for each SKU.
6. Application calculates COGS, GST, profit/loss, margins and other metrics.
7. User can analyze profit by:

   * Order
   * SKU
   * Product
   * Date
   * Month
8. User can export the final report.

The most important requirement is **accurate profit calculation using the actual Meesho payment report rather than simply calculating Selling Price − Purchase Price.**

---

# 2. IMPORTANT: USE THE PROVIDED MEESHO EXCEL STRUCTURE

The application must be designed to work with the Meesho Excel payment report provided by the user.

The workbook can contain sheets such as:

* `Order Payments`
* `Ads Cost`
* `Referral Payments`
* `Compensation and Recovery`

The primary sheet is:

`Order Payments`

The application should dynamically detect the actual columns instead of hard-coding Excel column letters.

The Meesho workbook may contain grouped/header rows.

For example, the first row can contain category/group names while the following row contains actual field names.

Therefore:

**DO NOT assume row 1 contains the real column headers.**

Automatically detect the row containing fields such as:

* Sub Order No
* Order Date
* Supplier SKU
* Quantity
* Final Settlement Amount

Then use that row as the actual header row.

# 7. PURCHASE GST CALCULATION

If purchase price including GST is ₹118 and GST rate is 18%:

Taxable Purchase Cost:

`118 / 1.18 = ₹100`

Input GST:

`118 - 100 = ₹18`

If quantity is 2:

Purchase amount paid:

`₹118 × 2 = ₹236`

Taxable COGS:

`₹100 × 2 = ₹200`

Input GST:

`₹18 × 2 = ₹36`

If the seller is eligible for Input Tax Credit, recoverable input GST should not be treated as a permanent business expense.

---

# 8. SELLING GST

Do NOT blindly calculate:

`Final Settlement Amount / 1.18`

The exact treatment must depend on the fields available in the Meesho report.

First inspect the workbook for actual GST/tax fields.

If Meesho provides an actual GST/tax amount relevant to the order, use that actual value.

If no relevant GST amount exists and the settlement needs to be estimated as GST-inclusive, then calculate using the configured Selling GST Rate and clearly label it:

**Estimated GST**

Never silently make an assumption.

---

# 9. VERY IMPORTANT: AVOID DOUBLE COUNTING MEESHO FEES

`Final Settlement Amount` is the key settlement figure.

The application must NOT do this:

`Final Settlement`
− Meesho Commission
− Shipping
− Fixed Fee
− Return Shipping
− GST
− Other Fees

if those charges have already been deducted in arriving at Final Settlement Amount.

That would double-count deductions.

Instead:

### Basic settlement profit

`Final Settlement Amount - Seller COGS`

Use the actual Meesho settlement figure.

Display Meesho fees separately for analysis, but do not subtract them again if already reflected in Final Settlement Amount.

---

# 10. PROFIT CALCULATION

For every order:

### Seller COGS

`Quantity × Purchase Cost Per Unit Including GST`

Also calculate:

### Taxable COGS

`Quantity × Purchase Cost Excluding Recoverable GST`

Then show two views.

---

# 11. CASH PROFIT VIEW

This shows the seller's actual cash economics.

### Cash Profit

`Final Settlement Amount - Actual Purchase Amount Paid`

Where:

`Actual Purchase Amount Paid = Quantity × Purchase Cost Including GST`

Example:

Settlement = ₹300

Quantity = 2

Purchase cost including GST = ₹100/unit

Purchase cost = ₹200

Cash Profit = ₹100

This is useful for understanding actual money remaining from the transaction.

---

# 12. ACCOUNTING PROFIT VIEW

If the seller is GST registered and eligible for Input Tax Credit:

Do not treat recoverable purchase GST as a business expense.

Use GST-exclusive COGS.

### Accounting COGS

`Purchase Cost Including GST - Eligible Input GST`

### Accounting Profit

Use the applicable GST-exclusive sales value/settlement basis supported by the Meesho report, minus GST-exclusive COGS and applicable expenses.

If the exact GST treatment cannot be established from the workbook, clearly label the number:

**Estimated Accounting Profit**

Do not pretend it is a tax-return calculation.
